# Agent 评测接入通用化方案（提案）

状态：Proposal。已提供[Preview 检查入口](agent-run-inspection.zh-CN.md)，覆盖事件完整性、实际输出摘要和声明字段比较；其他评测维度仍为候选设计。本文只定义 Cernora 的通用接入边界，不描述任何具体监控产品、内部命令、真实生产响应或私有运行器。

## 目标

让使用者可以把任意 Agent Runtime 的一次自然语言任务运行，转换为 Cernora 可验证的评测输入，并回答四个独立问题：

1. Agent 是否理解了用户意图；
2. Agent 是否选择并调用了正确工具及参数；
3. 工具是否成功返回了可验证事实；
4. 最终回答是否忠实于事实，并对证据不足的判断保持克制。

运行器、模型服务和工具服务仍由使用者负责；Cernora 只接收脱敏后的完成运行导出和权威参考。

## 建议输入契约

新增一个通用的 `agent-run-export/v1`（名称可在实现阶段确定），至少包含：

- `run_id`、`task_id`、`case_id` 和时间戳；
- 固定条件摘要：Agent、模型、Prompt 版本、预算和工具版本；
- 用户任务；
- 有序事件流：模型消息、工具调用、工具返回、错误和结束状态；
- 最终 Agent 回答；
- 工具输出的引用或脱敏快照及其摘要；
- 可选的人工作答和字段级参考。

未知字段、缺失身份、事件顺序错误、摘要不匹配或不完整导出必须进入 `inconclusive`/拒绝导入路径，不能静默转为通过。

## 评测层次

评测报告应分别记录：意图识别、首次正确工具调用、参数正确性、工具执行结果、事实字段准确率、无依据断言、行动建议边界、延迟、调用次数和成本。进程退出码只能作为一个观察字段，不能代替任务结果。

事实评分优先采用字段级确定性比较；语义 Judge 只能作为补充，并必须保留其输入、版本和不确定状态。没有人工参考或无法确认事件独立性时，结果应为 `inconclusive`。

## 数据集与实验

案例以独立事件为单位划分开发集和验证集。相同事件、同一批次或同一根因的切片必须放在同一集合。每次比较固定 Agent、模型、Prompt、预算和用户问题，只允许一个干预变量变化。报告同时给出收益、回归和成本，不能只报告最终成功率。

## 推荐实现顺序

1. 先实现导出契约校验和事件流归一化；
2. 增加工具调用与最终回答的独立统计；
3. 增加字段级事实评分和证据边界检查；
4. 增加开发/验证集声明与重复实验汇总；
5. 用合成 fixture 编写离线测试；
6. 在公开文档中提供最小接入教程和失败示例。

## 验收标准

- 不依赖特定厂商或内部工具名称即可导入一次 Agent Run；
- 能区分“未调用工具”“工具失败”“工具成功但回答错误”；
- 缺失或不可验证证据不会得到 `pass`；
- 同一导出重复评测产生字节稳定的结果；
- 公开 fixture 不包含生产数据、凭证、私有路径或内部实现；
- 现有 Cernora 评测内核和公共 Profile 兼容性不被破坏。
